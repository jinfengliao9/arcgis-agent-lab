## 必须遵守的约束

**接口**
- 保持公开签名：`verify_answer(actual, expected, *, contract=None, answer_type="", tolerance=None) -> bool | None`
- 返回值语义不变：`True` / `False` / **`None` = 待核验**（调用方会把 None 记为
  待核验，既不算通过也不算失败）
- 契约 schema 可以**扩展**（例如为 refusal 增加 `subject` 字段），但必须：
  - 同步给出 `tasks/build_tasks.py` 里 `ANSWER_CONTRACTS` 的更新
  - **缺字段时降级为待核验，而不是报错或猜**

**不能破坏的东西**
- `tests/` 下现有的 **90 个通过测试**必须继续通过（你可以读它们）
- 不新增第三方依赖（标准库之外一律不要）
- 不用 `\b` 处理中文边界（它在中日韩文字旁不成立，这是已经踩过的坑）
- 不要引入「全文出现某关键词就通过」这类规则 —— 前三轮的失败全部源于此

**设计原则（请遵守，如有异议请在回复里说明）**
- **先排除矛盾，再确认匹配**。顺序反过来就会继续产生错误通过。
- 解析不出来就返回 `None`，**不要猜**。宁可待核验，不要错误通过。
- 每条规则都应在代码注释里写清它对应哪个具体的失败案例。
